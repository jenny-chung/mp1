⏺ There are two separate pipelines in webpack.config.js, and both ship every
  asset.

  1. The loaders make hashed copies. When html-loader sees <img 
  src="assets/nizu.jpg">, <video poster> or <source src>, it bundles the file
  and rewrites the path. css-loader does the same for the font and
  background-image url()s in the SCSS. The files are emitted at the root of
  build/ with content-hashed names, such as 938b6511e4d354037d77.jpg. This is
  the copy the page actually loads.

  2. CopyPlugin copies the whole folder:
  new CopyPlugin({ patterns: [{ from: './assets/', to: './assets/' }] })
  This copies all of src/assets/ into build/assets/ as-is (15 MB). It came with
  the course template, as a fallback for paths set from JavaScript at runtime,
  which webpack can't see. The only thing still using those copies is the
  video's fallback "Download the clip instead" link: html-loader doesn't rewrite
  <a href>, so that link points at build/assets/video/matcha-whisk.mp4.
  Earlier, data.js had runtime image paths, but the lightbox now reads the image
  straight from each tile.

  Stale files: there's no output.clean setting, so webpack never deletes old
  output. build/ is currently 35 MB:
  - 15 MB in build/assets/ (the duplicates).
  - The live hashed files.
  - Leftovers from earlier builds, e.g. the first matcha clip (204db13…mp4), the
    old poster, and the image.jpg placeholder.

  The stale files only exist locally. build/ is gitignored and CI builds from a
  clean checkout, so they never reach GitHub Pages. The 15 MB of duplicates do
  get deployed.

  The fix is two small edits to webpack.config.js:
  1. Add clean: true to output, so each build starts from an empty folder.
  2. Remove the CopyPlugin block. Then either drop the fallback link (the
     fallback text stays), or leave it pointing at the hashed file. OFL.txt
     would also stop being copied, which is fine: the licence only needs to stay
     in the repo, not on the site.

  That brings the build down to about 20 MB, which is almost all your photos and
  the video. The plan marked webpack.config.js as "untouched", so I haven't
  changed it. Want me to make these edits and rerun the checks?
